## Code changes (uncommitted)

### Correctness and bugs

- `src/session.rs`, `src/observe.rs`: verify mode re-validates before declaring a mismatch; new `verify_raced` counter. Test `verify_mode_ignores_writes_racing_the_rerun` (now accepts raced verifications, since over a network nearly all race).
- `src/validator.rs`, `src/session.rs`: `min_query_time` excludes the network round trip. A ping worker runs `SELECT 1` every 2 s on a helper connection; `rtt()` is the fastest of the last 8; the forwarded time minus `rtt()` feeds the per-statement EWMA and `exec_micros`. Test `min_query_time_excludes_the_network_round_trip` (relay with 10 ms each way).
- `sql/schema.sql`: `changed_since` read the whole changelog under `validate()`'s generic plan (EXISTS over `xid >= xmax` planned as a seq scan). Now `ORDER BY xid DESC LIMIT 1`, one index probe. Test `validation_does_not_scan_the_changelog` (200,000 entries; counts `seq_tup_read`). On Fly this took hits from 1,471 back to about 8,000 tps after a write burst.

### Performance (the four requested improvements)

- 1, pipelined checks (`src/validator.rs`, `PIPELINE = 4`): each check connection keeps up to 4 batches in flight (`JoinSet`, `take_batch`, `run_and_reply`). Test `hits_take_one_round_trip_behind_a_slow_network` (16 clients behind a 20 ms round trip: 1.17 round trips per hit; 1.8 with depth 1). **Regression on low-latency networks, see Open items.**
- 3, one round trip per miss (`src/session.rs`, `src/validator.rs`): the fill's snapshot is `SNAPSHOT_SQL` (`pg_current_snapshot()`, `pg_is_in_recovery()`) pipelined on the client's connection through `our_query`; epoch and settings come from `fill_base()`, the context worker's latest read (every second, and right after a check reports a catalog change via `refresh_context()`); after the query the proxy pipelines the session fingerprint read (`refresh_fingerprint_behind`), so the next request doesn't spend a round trip on it. Test `a_miss_takes_one_round_trip_behind_a_slow_network` (2 round trips before, 1 after).
- 4, time before caching (`policy_skip` in `src/session.rs`): with `min_query_time > 0`, a statement shape is forwarded and timed once before it can be cached, then cached only while its EWMA is at or above the threshold. `min_query_time = 0` (tests, Python tests) is unchanged.
- 5, cheaper checks (`sql/schema.sql`): `catalog_epoch()` is one statement, `rel_state()` fingerprints built-in column types inline, `validate()` inlines the changelog lookup (keep it identical to `changed_since`). Fingerprints are byte-identical (digest over 52 tables matched). A/B over 2,000 calls: 0.27 ms to about 0.2 ms per check batch.

## Open items, in order

1. **Fix the pipelining regression.** v3 on Fly: hits 5,471 tps at 32 clients against 8,379 in v2, p50 5.6 ms against 3.6, Postgres time per hit 0.38 ms against 0.13, and both check backends saturated. Smaller, more frequent batches pay the fixed per-batch cost (about 0.3 ms) more often. Pipelining only pays when the round trip dominates. Plan: pipeline depth = round trip / measured batch execution time (batch round trip minus `rtt()`), clamped to 1..8; depth 1 until measured. That gives 1 on Fly (0.6 ms vs 0.35 ms) and 8 on Neon (24 ms). Keep `hits_take_one_round_trip_behind_a_slow_network`; add a test that depth stays 1 without the relay. Then rebuild (Depot), fetch v3 first, update Machines, run v4 on both targets, re-run the local benchmark.
